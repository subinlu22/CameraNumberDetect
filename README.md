# 산업용 카메라 뚜껑 검사 시스템 (CameraNumberDetect)

🔗 **Portfolio**: https://subinlu22.github.io

컨베이어벨트 위를 지나가는 뚜껑의 **색깔(화이트/파랑/빨강)과 숫자(1/2/3)를 실시간으로 인식**해서 양품/불량을 판정하고 카운트하는 프로그램입니다.
판정 결과는 UDP로 Unity 디지털트윈([CameraDigitalTwin](https://github.com/subinlu22/CameraDigitalTwin))에 전송됩니다.

> 📷 데모 영상 / 스크린샷 자리

## 주요 기능
- Hikrobot 산업용 카메라(GigE) SDK로 실시간 프레임 수신
- 배경 학습(MOG2)으로 벨트 무늬를 걸러내고 뚜껑 위치 검출
- HSV 기반 뚜껑 색 판정
- CNN(PyTorch 학습 → ONNX 변환 → C# ONNX Runtime 추론)으로 숫자 판정 (검증 정확도 99.3%, 748장)
- 같은 결과가 3프레임 연속 나오면 카운트 확정, 검사 로그 CSV 저장
- 대시보드 UI: 실시간 영상, 판정 결과, 양품/불량 통계, 검사 기준(색) 필터
- 벨트 이동 중 인식, 4cm 간격으로 연달아 올려도 카운트 누락 없음
- 배경 학습 결과 저장/불러오기 (시작 시 약 200초 → 몇 초)
- Unity 디지털트윈으로 검사 결과 UDP 전송 (포트 5053)

## 기술 스택
| 구분 | 사용 |
|---|---|
| 언어 / UI | C#, .NET 8, Windows Forms |
| 영상 처리 | OpenCvSharp (OpenCV) |
| 숫자 인식 | PyTorch (학습), ONNX Runtime (추론) |
| 하드웨어 | Hikrobot MV-CU050-30GC, 링라이트, 미니 컨베이어벨트 |
| 연동 | UDP (Unity) |

## 처리 흐름
```
카메라 프레임 → 1/3 축소 → 배경 학습 마스크(MOG2) → 원형 윤곽선으로 뚜껑 위치 검출
→ 색 판정(HSV) → 뚜껑 크롭 → 숫자 영역 전처리 → CNN 숫자 판정
→ 3프레임 연속 같은 결과면 카운트 + CSV 기록 + Unity로 UDP 전송
```

## 문제 해결 기록
| 문제 | 원인 | 해결 |
|---|---|---|
| 벨트 반사광·짜임이 뚜껑으로 잡힘 | 벨트 무늬, 레일 정반사 | MOG2 배경 학습 + 원형도 필터(볼록껍질 기준) + 레일 반사 물리적 차폐 |
| 정지 상태는 되는데 움직이면 실패 | 노출시간이 길어 모션블러로 원형이 무너짐 | MVS로 실측해 노출·게인 재설정 |
| 파랑/빨강 뚜껑만 숫자 오인식 | 글리터 입자를 숫자 픽셀로 오인 | 색 거리 계산 **전에** 블러 적용 (학습·추론 전처리 동일하게) + 새 조명 기준 재촬영·재학습 |
| 연달아 올리면 카운트 누락 | 잠금 해제 조건이 "뚜껑이 사라짐" 하나뿐이라 촘촘하면 안 풀림 | 벨트가 한 방향이라는 점을 이용, 위치가 뒤로 점프하면 새 뚜껑으로 판단 |
| 켤 때마다 배경 학습 200초 | MOG2는 학습 상태 저장 불가 | 학습 때 본 장면을 사진으로 저장했다가 다시 학습시키는 방식 |

## 배운 점
- 소프트웨어를 고치기 전에 조명·노출 같은 물리 환경부터 확인하기
- 원인을 짐작으로 고치지 않고, 조건을 나눠 비교하거나 로그로 먼저 확인하기
- 모델 입력을 직접 눈으로 확인하는 게 가장 확실한 디버깅
